
## Current answer-handler seam review (2026-11-20)
- **VERIFIED:** Hiragana quiz choice press checks whether a choice is already selected (the button becomes disabled), then calls the correctness predicate, updates selected-answer UI state, and appends `{character: question.prompt, correct}` to in-memory attempts. This is a single callback; there is no awaited persistence boundary today.
- **VERIFIED:** Row selection and `startPractice()` reset the attempts array and question index, so session identity must be generated at session start and attempt/event identity must be generated at the accepted answer, not inferred from question index alone.
- **INFERRED:** The persistence seam should accept an explicit immutable snapshot of the prompt (canonical script + character ID + displayed prompt metadata/content revision), choice outcome, presentation/answer timestamps, and generated event ID. It must not read mutable React state after the await. The user action callback will need an explicit async ordering contract to prevent UI advancement before durable write; test this callback with a fake writer before native DB integration.
- **UNKNOWN:** Full Katakana UI handler read remains unavailable via the GitHub file endpoint; current Katakana pure functions and earlier targeted audit establish its parallel local state shape, but no detailed handler ordering claim is made here.
- **Key correction to schema proposal (INFERRED):** Current kana practice uses static in-app character constants, not the synthetic SQLite glossary pack. Review-event content identity therefore should use a stable kana dataset/revision identifier plus canonical script and character key. A glossary-pack ID/version field can remain nullable/future-only for vocabulary review, or be replaced with a source-neutral content identity envelope. Avoid requiring a glossary pack identity for kana events.
