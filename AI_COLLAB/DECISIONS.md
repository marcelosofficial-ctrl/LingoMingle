# DECISIONS
## Accepted
D001 Separate private repo per project.
D002 Expo SDK 58 + React Native + TypeScript pinned in package.json.
D003 SQLite local-first; no mandatory account/server.
D004 Hiragana MVP, then katakana/Hangul, then Song Study.
D005 Freemium is future candidate, not first-slice scope.
D006 Reuse compatible permissively licensed packages/data; exclude GPL/AGPL/SSPL/NC/ND/unlicensed code/content.
D007 v1 media uses user-imported, original, public-domain or properly licensed text. No scraping.
D008 All spending blocked until explicit user approval.
D009 PWA and Android APK are no-store-fee paths, not equivalents to official stores.
D010 Canonical repository is marcelosofficial-ctrl/LingoMingle, selected explicitly by user on 2026-11-11. All new work belongs here.
D011 Glossing is a separate offline lexical layer, never conflated with transliteration, IME conversion or sentence translation. Japanese and Korean morphology adapters return exact token surface + lemma/reading/POS as appropriate. Lookup rejects stale/mismatched analyzer surfaces and Korean morphology tokens containing internal whitespace.
D012 POS comparisons require an explicit versioned tag namespace (scheme + tag). Never compare Kiwi Sejong-derived tags directly to NIKL dictionary POS labels. Exact surface matches may bypass morphology.
D013 Kiwi v0.24.1 is the preferred Korean morphology proof candidate, not an adopted dependency. Use native AAR/Swift bindings for native app and keyboard targets; reserve WASM for web unless a tested native worker bridge exists. Do not bundle the 87.97 MB model until extension RAM/size and offline loading pass.
D014 Map Kiwi Sejong and NIKL POS tags into lingomingle-pos-v1 only where unambiguous. Preserve raw source scheme/tag. Kiwi VX, VCP/VCN and non-lexical tags remain unresolved; unresolved POS cannot satisfy Korean lemma matching.
D015 NIKL text data is CC BY-SA 2.0 KR under the official copyright policy unless separately marked; commercial reuse requires attribution and share-alike for adaptations. Multimedia rights are individually set and excluded. Keep NIKL-derived data in a separate licence zone; do not import a snapshot until the official export schema, fields and notices are inspected.
D016 The inspected NIKL 2026-10-19 full JSON supports a technical GO for a word-only offline Korean-English glossary: 51,555 word entries with unique IDs; 49,869 entries have English translations for every sense (69,431 senses). V1 excludes non-word lexical units and incomplete-translation entries, plus examples, audio/pronunciation, conjugations and multimedia. Production import/distribution remains HOLD pending qualified CC BY-SA 2.0 KR/platform review. No real dataset or production DB is imported.
D017 GlossSense.englishEquivalent is an optional sense-level field distinct from englishGloss, because the NIKL bulk JSON stores English equivalent lemma and definition separately.
D018 The NIKL record normalizer is dependency-free and record-level only. It accepts synthetic-tested word records with complete English sense coverage, rejects malformed/duplicate IDs, and drops all examples/media/pronunciation/conjugation/variants. No ZIP streaming, production import or distribution is authorized by this prototype; the caller must abort a pack build on any rejection.
D019 NIKL source processing is build-time only. The 1.016 GB archive must never be parsed on-device. Future importer uses bounded ZIP/JSON streaming, CRC/size/path checks, synthetic-only fixtures, deterministic JSONL and verified temporary DB publication. No archive upload, app dependency or real-data import without separate approval.
D020 NIKL store distribution remains HOLD. CC BY-SA 2.0 KR, Apple's FairPlay/Standard or Custom EULA and Google Play DDA interaction require qualified counsel review before bundling or shipping a derived pack.
D021 T012's Node streaming package is an isolated build-tool prototype only, not an app dependency. It accepts synthetic fixture filenames only, enforces ZIP/JSON/record bounds and uses zip.js 2.25.0, stream-json 3.9.0 and stream-chain 4.4.2. Upstream says stream-json is not designed for hostile JSON; do not run this prototype on the actual NIKL archive. Real import still requires a separate source-trust/parser review and legal clearance.

D022 The glossary pack builder is a private build-time-only tool using Node 22.13.1 node:sqlite DatabaseSync. It is synthetic-fixture-only, schema v1, and maps the current GlossSource/GlossEntry/GlossSense contract with normalized lookup indexes. Node's SQLite API remains experimental (Stability 1.1), so it must not enter Expo runtime or public API surfaces. No actual NIKL import or store distribution is authorized.

D023 T014 adds a read-only app repository for schema-v1 glossary packs. The app does not own pack migrations and does not open/create/copy files during lookup. Factory input is a dedicated, already-open SQLite connection; it validates application_id 0x4c4d474c, user_version 1 and required tables, then enables PRAGMA query_only=ON. The repository exposes no DB handle or write API and closes its owned connection idempotently. Provisioning/installing an existing pack is a separate T015 boundary. No real NIKL import or distribution is authorized.

D024 T015 defines a hash-gated immutable glossary-pack install. The reserved v1 pack filename is app-owned. Reuse requires matching SHA-256 and SQLite integrity/FK/application/schema/table/count checks, followed by query_only. Install copies to same-directory staging, validates, moves to final and validates again. Expo File.move atomicity is undocumented; do not claim atomic rename and hash-gate every open to recover partial final files after interruption. Never use SQLiteProvider assetSource as a verified replacement: SDK source returns without copying when a destination already exists and native copy paths are not documented atomic. No real NIKL pack or store distribution is authorized. T015 also verifies the exact v1 table column layouts and serializes same-path concurrent provisioning, returning distinct SQLite connections.

D026 T016 SDK 58 FileSystem contract: pin expo-file-system 58.0.13 only, matching the current task scope. SDK 58 source confirms MIT, no runtime dependencies, peer dependencies expo/react-native, File.digest("SHA-256"), and File copy/move/delete. File copy/move destinations accept File|Directory, so adapt through wrappers rather than unsafe structural casts. Always use SQLite.defaultDatabaseDirectory for staging/final and call openDatabaseAsync only after T015 validation. The previous expo-asset proposal is not adopted because current NEXT_TASK explicitly says add only expo-file-system; asset-to-local-File resolution must be demonstrated without adding an undeclared dependency or the task must be explicitly revised. This is a source/API decision only; no runtime behavior is verified.


D027 T015 red-team correction (2026-11-15): a different SHA-256 at the reserved v1 filename is not permission to delete the existing file. Provisioning now stages, hashes and validates the replacement before inspecting the final path. If the existing final file independently passes the full schema/integrity/FK/count/query_only checks but has different content, fail closed with glossary-pack-destination-valid-content-conflict; preserve the existing file and clean staging. A v1 filename is immutable: a future content revision needs a new filename/schema migration. Final-file cleanup after a failed operation is allowed only after the current attempt has entered publication. This supersedes D024's broad statement that any mismatched final file may be replaced after source-hash verification. Runtime/native crash behavior remains unverified.

D028 T016 bundled-asset resolution (2026-11-15): the exact Expo release tag expo@58.0.24 has expo-asset 58.0.21 as a direct dependency of expo (MIT). SDK 58 Asset.fromModule accepts the numeric Metro require() asset ID; downloadAsync supplies a localUri in OS cache, which is not durable. Use that localUri only as the hash-checked source and copy into SQLite.defaultDatabaseDirectory through FileSystem staging. No additional direct expo-asset version pin is needed for this task. Bundle a synthetic .db asset and add the extension to Metro assetExts. File digest must match a build-time SHA-256 constant before T015 opens it. Native behavior remains NOT RUN.
